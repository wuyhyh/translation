如果我们要擦除包含程序代码的闪存（Flash）内存位置，必须格外小心，特别是当我们删除包含向量表（vector table）的第一个扇区/页面时（如果执行的是整片擦除，这种情况总是成立的）。在这种情况下，我们需要将程序代码移动并重新定位整个向量表到 SRAM 中，如第 20 章所示，否则一旦中断触发，就会发生故障。

### 21.2.3 闪存编程

一旦扇区/页面被擦除，我们就可以继续对其内容进行编程。从理论上讲，完全可以通过直接访问闪存位置来更改其内容⁶，编写如下 C 代码：

```text
...
*(volatile uint16_t*)0x0800AA00 = Data;
...
```

然而，由于两个主要原因，这样做基本上是不方便的。首先，在某些 STM32 微控制器中，在编程闪存位置之前可能需要执行一些预备操作（例如设置特定的寄存器）。其次，根据具体的 STM32 系列和 VDD 电压范围，可以同时传输到闪存的字节数可能会有显著差异。基于这些原因，HAL 定义了以下函数：

⁶显然，在修改闪存之前必须先将其解锁。

<!-- page: 571 -->

```text
HAL_StatusTypeDef HAL_FLASH_Program(uint32_t TypeProgram, uint32_t Address, uint64_t Data);
```

该函数旨在抽象所有具体的实现细节。让我们分析一下函数的参数：

- TypeProgram：它指示写入操作期间传输了多少字节，它可以取值为 FLASH_TYPEPROGRAM_HALFWORD、FLASH_TYPEPROGRAM_WORD 和 FLASH_TYPEPROGRAM_DOUBLEWORD。请注意，此参数仅指定使用 HAL_FLASH_Program() 函数传输的数据量。单次事务中实际传输的字节数取决于 STM32 系列以及并行度（如果可用）。
- Address：它是开始放置内容的初始内存地址。
- Data：它是存储在闪存内存位置中的数据（表示为双字变量）。

与之前看到的擦除过程类似，可以使用以下函数在中断模式下执行闪存编程过程：

```text
HAL_StatusTypeDef HAL_FLASH_Program_IT(uint32_t TypeProgram,
uint32_t Address, uint64_t Data);
```

### 21.2.4 编程和擦除期间的闪存读取访问

在擦除或写入操作正在进行时，对闪存内存的读取访问会导致总线停顿（bus stall），至少在大多数 STM32 微控制器中是如此⁷。这意味着，如果你需要并行执行其他操作，你需要将要在闪存编程操作期间执行的代码重新定位到 SRAM 中。一个典型的场景是自定义引导加载程序（bootloader）：我们可以编程代码，以便使用 UART 在中断或 DMA 模式下将新固件交换到闪存中。在这种情况下，我们不能丢失异步事件（例如，通知数据传输的中断），因为 MCU 正在停顿等待正在进行的完成。如果是这样，最好将代码重新定位到 SRAM 中（并最终重新定位向量表）。

## 21.3 选项字节

选项字节是两个或更多字节，其位是特殊的配置值。选项字节的概念与其他微控制器架构中的概念类似，例如 Atmel AVR 系列中的熔丝（fuses）或 Microchip PIC 微控制器中的配置位（Configuration Bits）。

信息块区域中这些特殊字节的每个单独位都有特殊的含义。配置参数的数量和类型取决于具体的 STM32 微控制器。最常见的配置参数与以下方面相关：

⁷在某些 STM32 微控制器中，例如 STM32L0 系列，如果我们在半页编程操作正在进行时尝试访问闪存内存，可能会发生总线故障。更多信息，请查阅你所考虑的微控制器的参考手册。

<!-- page: 572 -->

- BOOT：在大多数 STM32 微控制器中，两个选项位允许选择启动源（FLASH、系统内存或 SRAM）。
- RDP：这些位设置闪存内存的读保护级别，我们将在本章后面更深入地分析它们。
- BOR_LEVEL：这些位包含激活/释放复位的电源电平阈值。可以写入以编程新的 BOR 级别。默认情况下，BOR 是关闭的。当电源电压 (VDD) 低于选定的 BOR 级别时，会产生器件复位。
- MCU 在进入某些低功耗模式时的行为：在几乎所有 STM32 微控制器中，都可以配置 MCU，使其在进入停止（stop）或睡眠（sleep）低功耗模式时产生复位。
- 硬件看门狗：在某些 STM32 微控制器中，存在一个或两个位用于以“硬件模式”配置 WWDG 和 IWDG，即它们在 MCU 复位时自动启动。
- 闪存写保护：这些位允许单独写保护某些闪存扇区/页面，即使闪存内存已解锁，也防止向其写入。如果给定位设置为 '1'，则对应的扇区/页面不受写保护；如果位设置为 '0'，则扇区/页面受写保护。

要编程选项字节，需要遵循特定的程序，该程序独立于整个闪存内存的编程。因此，CubeHAL 提供了专用的例程供使用。

首先，必须通过调用以下函数来解锁该区域：

```text
HAL_StatusTypeDef HAL_FLASH_OB_Unlock(void);
```

接下来，使用以下函数完全编程给定的选项字节：

```text
HAL_StatusTypeDef HAL_FLASHEx_OBProgram(FLASH_OBProgramInitTypeDef *pOBInit);
```

选项字节的值通过首先擦除信息块，然后使用传递给 HAL_FLASHEx_OBProgram() 例程的值编程所有选项字节来自动修改。该函数接受 C 结构体 FLASH_OBProgramInitTypeDef 的一个实例，其字段表示给定选项字节的内容。有关字段的确切类型和数量的更多信息，请查阅 CubeHAL 的源代码。

类似地，要检索给定选项字节的内容，我们使用以下函数：

```text
void HAL_FLASHEx_OBGetConfig(FLASH_OBProgramInitTypeDef *pOBInit);
```

一旦选项字节被修改，我们必须使用以下函数强制 MCU 重新加载其内容：

<!-- page: 573 -->

```text
HAL_StatusTypeDef HAL_FLASH_OB_Launch(void);
```

请注意，在某些 STM32 微控制器中更改某些选项位可能会导致芯片复位。

最后，ST STM32CubeProgrammer 提供了轻松修改选项字节的功能。一旦你将 ST-LINK 调试器连接到目标 MCU，点击选项字节图标（左侧第三个绿色图标）。将出现选项字节部分，如图 21.1 所示。相同的 STM32CubeProgrammer 工具还允许擦除选定的闪存扇区/页面。
