# 1. STM32 微控制器产品组合简介

本章对 STM32 整个产品组合进行简要介绍。其目的是向读者介绍这个相当复杂的微控制器家族，该家族细分为十七个不同的子系列。这些子系列共享一组共同特性，同时各自具备特定系列独有的功能。此外，本章还将对 Cortex-M 架构进行简要介绍。本章无意成为 Cortex-M 架构或 STM32 微控制器的完整参考手册，而是旨在为读者提供一份指南，帮助他们在超过 1200 款微控制器中选出最适合自身开发需求的那一款——毕竟，面对如此庞大的选择范围，要做出决定并不容易。

## 1.1 ARM 处理器简介

如今，"ARM"一词既指众多精简指令集计算（RISC）架构家族，也指多个完整的内核家族。这些内核是许多芯片制造商所生产的 CPU 的基本构建模块（因此称为"核"）。在涉及 ARM 处理器时，由于存在许多不同的 ARM 架构修订版本（ARMv6、ARMv6-M、ARMv7-M、ARMv7-A、ARMv8-M 等）以及许多基于这些架构修订版本的核心架构，很容易产生混淆。为了便于理解，例如，基于 Cortex-M4 内核的处理器就是按照 ARMv7-M 架构设计的。

ARM 架构是一组规范，涵盖指令集、执行模型、内存组织与布局、指令周期等方面，精确描述了一台将实现该架构的机器。如果你的编译器能够为该架构生成汇编指令，那么它就能够为所有实现该架构的实际机器（即处理器）生成机器代码。

Cortex-M 是一组物理内核家族，设计用于与厂商特定的硅器件进一步集成，从而构成完整的微控制器。内核的工作方式不仅由其对应的 ARM 架构（如 ARMv7-M）定义，还由芯片制造商所集成的外设和硬件能力决定。例如，Cortex-M4 内核架构设计为支持在两个特定内存区域中使用一种称为位带（bit-banding）的特性进行位数据访问操作，但是否实际添加该特性取决于具体的实现方案。STM32F1 是基于 Cortex-M3 内核的微控制器系列，实现了该位带特性。图 1.1 清晰地展示了基于 Cortex-M3 的微控制器与其 Cortex-M3 内核之间的关系。

ARM Holdings 是一家英国公司，为日本软银（Softbank）控股集团的子公司，负责开发 ARM 产品的指令集和架构，但不制造器件。这是 ARM 世界的一个重要特点，也是众多芯片制造商能够基于 ARM 架构和内核开发、生产并销售微控制器的原因。ST 微电子（ST Microelectronics）就是其中之一，目前也是少数销售完整 Cortex-M 处理器产品组合的制造商之一。

ARM Holdings 既不制造也不销售基于自身设计的 CPU 器件，而是将处理器架构授权给相关方。ARM 提供多种授权条款，在费用和交付物方面各不相同。在提及 Cortex-M 内核时，也常使用知识产权（IP）核这一说法，指的是被视为某一方（即 ARM Holdings）知识产权的芯片设计版图。

得益于这种商业模式以及低功耗能力、某些架构的低生产成本等重要特性，ARM 在数量上是最广泛使用的指令集架构。基于 ARM 的产品已变得极为流行。截至 2020 年，已生产超过 1600 亿颗 ARM 处理器。基于 ARM 的处理器装备了全球约 95% 的移动设备。许多主流且广受欢迎的 64 位多核 CPU，用于已成为电子行业标志性的设备（如 Apple 的 iPhone），都是基于 ARM 内核的。近年来，Apple 发布了 Apple M1，这是一款基于 ARMv8.5-A 架构的 ARM 片上系统（system on chip）（SoC），由 Apple 自行设计，作为其 Macintosh 计算机和 iPad Pro 平板电脑的中央处理器（CPU）和图形处理器（GPU）。

作为一种广泛采用的标准，有大量编译器和工具，以及操作系统（Linux 是 Cortex-A 处理器上最常用的操作系统）支持这些架构，为开发者提供了丰富的应用构建机会。

### 1.1.1 Cortex 和基于 Cortex-M 的处理器

ARM Cortex 是一组在嵌入式领域广受欢迎的 32/64 位架构和内核。Cortex 微控制器分为三个主要子系列：

- Cortex-A，其中 A 代表 Application（应用），是一系列为执行复杂计算任务的设备提供多种解决方案的处理器，例如承载丰富的操作系统（OS）平台（Linux 及其衍生系统 Android 最为常见），并支持多个软件应用。Cortex-A 内核装备了大多数移动设备（如手机和平板电脑）中的处理器。在这一市场细分中，我们可以找到多家芯片制造商，从销售目录产品的厂商（TI、Freescale 以及 STM 的 STM32MP1）到为其他被许可方生产处理器的厂商。在这一系列中最常见的内核中，有广受欢迎的 32 位 Cortex-A7 和 Cortex-A9 处理器（它们仍然常见于多款廉价单板计算机（SBC）上），以及最新的超高性能 64 位 Cortex-A77 和 Cortex-A78 内核。
- Cortex-M，其中 M 代表 eMbedded（嵌入式），是一系列可扩展、兼容、节能且易于使用的处理器，专为低成本嵌入式市场设计。Cortex-M 系列针对成本和功耗敏感的 MCU 进行了优化，适用于物联网、连接性、电机控制、智能计量、人机界面设备、汽车和工业控制系统、家用家电、消费电子产品和医疗器械等应用。在这一市场细分中，我们可以找到许多生产 Cortex-M 处理器的芯片制造商，ST Microelectronics 就是其中之一。
- Cortex-R，其中 R 代表 Real-Time（实时），是一系列为嵌入式系统提供高性能计算解决方案的处理器，在这些系统中，可靠性、高可用性、容错性、可维护性和确定性实时响应至关重要。Cortex-R 系列处理器提供快速且确定性的处理和高性能，同时满足苛刻的实时约束。它们将这些特性集成为性能、功耗和面积优化的封装，使其成为要求容错性的可靠系统中的可靠之选。

接下来的章节将介绍 Cortex-M 处理器的主要特性，尤其是从嵌入式开发者的角度来看。

#### 1.1.1.1 内核寄存器

与所有 RISC 架构一样，Cortex-M 处理器是加载/存储（load/store）型机器，它们仅对 CPU 寄存器执行操作，¹ 但有两类指令除外：加载和存储指令，用于在 CPU 寄存器和内存位置之间传输数据。

¹这并不完全正确，因为 ARMv6/7 架构中还有其他可以访问内存位置的指令，但就本讨论而言，最好将该句视为正确。

<!-- page: 35 -->

图 1.2 展示了 Cortex-M 内核寄存器。其中一些寄存器仅在 M3、M4 和 M7 等更高性能系列中可用。R0-R12 是通用寄存器（general-purpose register），可作为 ARM 指令的操作数。然而，某些通用寄存器可被编译器用作具有特殊功能的寄存器。R13 是堆栈指针（stack pointer）（SP）寄存器，也被称为分组的（banked）寄存器。这意味着该寄存器的内容会根据当前 CPU 模式（特权模式或非特权模式）而变化。此功能通常被实时操作系统（RTOS）用于执行上下文切换（context switching）。

接下来的 0.5GB 内存专门用于外设映射。MCU 提供的每个外设（定时器、I²C 和 SPI 接口、USART 等）在该区域都有一个别名。具体由哪个 MCU 来组织此内存空间。

接下来的 2GB 区域专门用于外部 SRAM 或闪存。Cortex-M 器件可以通过 EMI/FSMC 接口从外部内存执行代码并加载/存储数据，从而扩展内部内存资源。一些 STM32 器件，如 STM32F7，能够借助 L1 缓存和 ARTTM 加速器，从外部内存执行代码而不会遇到性能瓶颈。

最后的 0.5 GB 内存分配给内部（内核）Cortex 处理器外设，以及为未来 Cortex 处理器增强功能保留的区域。所有 Cortex 处理器寄存器在所有基于 Cortex 的微控制器中都位于固定位置。这使得代码更容易在不同的 STM32 变体之间移植，实际上也可以移植到其他供应商的基于 Cortex 的微控制器。

#### 1.1.1.3 位带操作 (Bit-Banding)

在嵌入式应用中，使用位掩码（bit masking）处理字（word）中的单个位是非常常见的。例如，假设我们要设置或清除无符号字节（unsigned byte）的第 3 位（即 bit 2）。我们可以简单地使用以下 C 代码来实现：

```text
...
uint8_t temp = 0;
temp |= 0x4;
temp &= ~0x4;
...
```

当我们希望节省内存空间（使用单个变量并为其每一位赋予不同的含义）或者必须处理微控制器内部寄存器和外围设备时，会使用位掩码。

如我们所见，如此简单的操作需要三条汇编指令（取数、修改、保存）。这导致了两种类型的问题。首先，这三条指令造成了 CPU 周期的浪费。其次，如果 CPU 处于单任务模式且只有一个执行流，该代码工作正常；但如果我们处理的是并发执行，另一个任务（或仅仅是中断例程）可能会在我们完成“位掩码”操作之前影响内存内容（例如，在上述汇编代码中，中断发生在第 0xC-0x10 行或 0x14-0x18 行指令之间）。

位带操作（Bit-banding）是一种将给定内存区域的每一位映射到别名位带内存区域（aliased bit-banding memory region）中一个完整字（word）的能力，从而允许对该位进行原子访问。图 1.5 展示了 Cortex 内核如何将内存地址 0x2000 0000 的内容映射到位带区域 0x2200 0000-1c。例如，如果我们想要修改 0x2000 0000 内存位置（bit 2），我们只需访问 0x2200 0008 内存位置即可。

```text

```

#### 1.1.1.4 Thumb-2 与内存对齐

从历史上看，ARM 处理器提供 32 位指令集。这不仅允许拥有丰富的指令集，而且保证了在执行涉及算术运算以及内核寄存器与 SRAM 之间内存传输的指令时获得最佳性能。然而，32 位指令集在固件的内存占用方面是有代价的。这意味着使用 32 位指令集架构（Instruction Set Architecture, ISA）编写的程序需要更多的闪存存储字节数，这会影响微控制器（MCU）的功耗和整体成本（硅晶圆价格昂贵，制造商不断缩小芯片尺寸以降低其成本）。

为了解决这些问题，ARM 引入了 Thumb 16 位指令集，它是常用 32 位指令集的一个子集。Thumb 指令每条长度为 16 位，并自动“转换”为对处理器模型具有相同效果的相应 32 位 ARM 指令。这意味着 16 位 Thumb 指令在实时情况下被透明地扩展（从开发者的角度来看）为完整的 32 位 ARM 指令，且没有性能损失。Thumb 代码的大小通常是 ARM 代码的 65%，并在从 16 位内存系统运行时提供后者 160% 的性能；然而，在 Thumb 中，16 位操作码的功能较少。例如，只有分支可以是条件性的，并且许多操作码被限制为只能访问 CPU 通用寄存器的一半。随后，ARM 引入了 Thumb-2 指令集，它是 16 位和 32 位指令

<!-- page: 42 -->

集在一种操作状态下的混合。Thumb-2 是一种可变长度指令集，与 Thumb 指令集相比提供了更多的指令，并实现了相似的代码密度。

![Image from PDF page 42](../images/page-0042-image-01.jpeg)

图 1.7：对齐内存访问与非对齐内存访问的区别

Cortex-M3/4/7 被设计为支持完整的 Thumb 和 Thumb-2 指令集，其中一些还支持专门用于浮点运算（Cortex-M4/7）和单指令多数据（SIMD）运算（也称为 NEON 指令）的其他指令集。

Cortex-M3/4/7 内核的另一个有趣特性是能够进行非对齐内存访问。基于 ARM 的 CPU 传统上能够访问字节（8 位）、半字（16 位）和字（32 位）的有符号和无符号变量，而不会像 8 位 MCU 架构那样增加汇编指令的数量。然而，早期的 ARM 架构无法执行非对齐内存访问，导致内存位置的浪费。

为了理解这个问题，请考虑图 1.7 中的左侧图表。这里有八个变量。内存对齐访问意味着，要访问字变量（图中的 1 和 4），我们需要访问 32 位（4 字节）的倍数地址。也就是说，字变量只能存储在 0x2000 0000、0x2000 0004、0x2000 0008 等位置。任何尝试访问不是 4 的倍数的位置都会导致 UsageFaults 异常。因此，以下 ARM 伪指令是不正确的：

```text

```

半字访问也是如此：可以访问存储在 2 字节倍数位置的内存位置：0x2000 0000、0x2000 0002、0x2000 0004 等。这种限制会导致 RAM 内存中的碎片化。为了解决这个问题，基于 Cortex-M3/4/7 的 MCU 能够执行非对齐内存访问，如图 1.7 中的右侧图表所示。我们可以看到，变量 4 从地址 0x2000 0007 开始存储（在早期 ARM 架构中，这仅对单字节变量是可能的）。这允许我们将变量 5 存储在内存位置 0x2000 000b，从而导致变量 8 存储在 0x2000 000e。内存现在被紧密打包，我们节省了 4 字节的 SRAM。

然而，非对齐访问仅限于以下 ARM 指令：

- LDR, LDRT
- LDRH, LDRHT
- LDRSH, LDRSHT

#### 1.1.1.5 流水线

每当我们要谈论指令执行时，我们都在做一系列非平凡的假设。在执行指令之前，CPU 必须从内存中获取并解码它。这个过程消耗几个 CPU 周期，具体取决于内存和内核 CPU 架构，这会增加到实际指令成本（即执行给定指令所需的周期数）中。

现代 CPU 引入了一种并行化这些操作的方法，以提高其指令吞吐量（单位时间内可以执行的指令数量）。基本指令周期被分解为一系列步骤，就好像指令沿着流水线行进一样。而不是按顺序处理每条指令（一次一条，在完成一条指令之前不开始下一条），每条指令被拆分为一系列阶段，以便不同的步骤可以并行执行。

![Image from PDF page 43](../images/page-0043-image-01.jpeg)

图 1.8：三级指令流水线

所有基于 Cortex-M 的微控制器都引入了某种形式的流水线。最常见的是三级流水线，如图 1.8 所示。Cortex-M0/3/4 支持三级流水线。专门用于低功耗 MCU 的 Cortex-M0+ 内核提供二级流水线（尽管流水线有助于减少与指令获取/解码/执行周期相关的时间成本，但它引入了必须在低功耗应用中最小化的能量成本）。Cortex-M7 内核提供六级流水线。

在处理流水线时，分支是一个需要解决的问题。程序执行的所有内容都是关于采取不同的路径；这是通过分支（如果相等则跳转）实现的。不幸的是，分支会导致流水线流失效，如图 1.9 所示。最后两条指令已被加载到流水线中，但由于选择了可选的分支路径而被丢弃（我们通常将它们称为分支阴影）

#### 1.1.1.6 中断与异常处理

中断和异常管理是基于 Cortex-M 处理器的最强大功能之一。中断和异常是改变程序流程的异步事件。当发生异常或中断时，CPU 会暂停当前任务的执行，保存其上下文（即堆栈指针），并开始执行一个专门用于处理该中断事件的例程。对于异常，该例程称为异常处理程序（Exception Handler）；对于中断，则称为中断服务例程（Interrupt Service Routine, ISR）。在异常或中断处理完成后，CPU 恢复之前的执行流程，之前的任务可以继续执行⁹。

⁸https://bit.ly/1k7ggh6 ⁹术语“任务”指的是一系列构成主执行流程的指令。如果我们的固件基于操作系统，场景可能会稍微复杂一些。此外，在低功耗睡眠模式下，CPU 可能被配置为在中断管理例程执行完毕后重新进入睡眠状态。我们将在后续章节中分析这些更复杂的场景。

除了前三个异常外，每个异常都可以分配一个优先级级别，该级别定义了并发中断时的处理顺序：数字越小，优先级越高。例如，假设我们有两个与外部输入 A 和 B 相关的中断例程。我们可以为输入 A 分配较高的优先级（较小的数字）。如果在处理器正在处理来自输入 B 的中断时，与 A 相关的中断到达，则 B 的执行将被暂停，以便立即执行优先级较高的中断服务例程。

异常和中断都由一个称为嵌套向量中断控制器（Nested Vectored Interrupt Controller, NVIC）的专用单元处理。NVIC 具有以下特性：

- 灵活的异常和中断管理：NVIC 能够处理来自外设的中断信号/请求以及来自处理器内核的异常，允许我们在软件中启用/禁用它们（NMI¹⁰ 除外）。
- 嵌套异常/中断支持：NVIC 允许为异常和中断分配优先级级别（前三种异常类型除外），从而可以根据用户需求对中断进行分类。
- 向量化的异常/中断入口：NVIC 自动定位与异常/中断相关的异常处理程序的位置，无需额外代码。
- 中断屏蔽：开发人员可以自由地暂停所有异常处理程序（NMI 除外）的执行，或者基于优先级级别暂停其中一些，这得益于一组专用寄存器。这允许以安全的方式执行关键任务，而无需处理异步中断。
- 确定性的中断延迟：NVIC 的一个有趣特性是中断处理的确定性延迟，对于所有 Cortex-M3/4 内核为 12 个周期，对于 Cortex-M0 为 15 个周期，对于 Cortex-M0+ 为 16 个周期，无论处理器的当前状态如何。
- 异常处理程序的重定位：正如我们稍后在书中将看到的，异常处理程序可以重定位到其他闪存内存位置，甚至完全不同——甚至是外部的——非只读内存。这为高级应用提供了极大的灵活性。

#### 1.1.1.8 电源模式

当前电子行业，尤其是移动设备设计领域，主要趋势在于电源管理。将功耗降至最低是所有参与电池供电设备开发的硬件设计师和程序员的主要目标。Cortex-M 处理器提供多个级别的电源管理，可分为两大类：固有特性和用户定义的电源模式。

所谓固有特性，是指在设计 Cortex-M 内核（内核）和整个微控制器（MCU）时定义的与功耗相关的原生能力。例如，Cortex-M0+ 内核仅定义了两个流水线级，以减少指令预取期间的功耗。另一个与电源管理相关的原生行为是 Thumb-2 指令集的高代码密度，这使得开发人员可以选择具有较小闪存存储器的微控制器，从而降低功耗需求。

#### 1.1.1.9 TrustZoneTM

ARM 最近推出了两款名为 Cortex-M23 和 Cortex-M33 的新 Cortex-M 处理器内核，两者均基于 ARMv8-M 架构。这些新内核继承了一个在大多数 Cortex-A 处理器中已经存在的特性：ARM TrustZoneTM。TrustZoneTM 是一个可选的安全扩展，旨在为广泛的嵌入式应用提供改进系统安全性的基础。TrustZoneTM 技术的概念并不新鲜。处理器可以运行在安全（Secure）和非安全（Non-secure）状态，非安全软件只能访问非安全内存区域。通过操作内存映射配置，可以定义内存地址空间中的区域，使得只有当处理器运行在安全模式时，才能访问该区域（无论是执行代码还是访问数据）。ARM TrustZoneTM 技术使系统和软件能够划分为安全世界（Secure world）和普通世界（Normal world）。安全软件可以访问安全和非安全内存以及硬件资源，而普通软件只能访问非安全内存和资源。这些安全状态与现有的线程模式（Thread mode）和处理程序模式（Handler mode）正交（后文将详细介绍这两种运行模式），从而允许在安全和非安全状态下都存在线程模式和处理程序模式。

¹¹来源 ST AN3430

ARM TrustZone 技术并不涵盖安全性的所有方面。例如，它不包括加密。在具有 TrustZoneTM 的 ARMv8-M 架构设计中，对系统安全至关重要的组件可以放置在安全世界中。例如，这些关键组件可能包括：

- 安全引导加载程序（Secure boot loader）
- 秘密密钥（Secret keys）
- 闪存编程支持（Flash programming support）
- 高价值资产（High value assets）

其余的应用程序通常放置在普通世界中。

#### 1.1.1.10 CMSIS

ARM 平台（无论是对于芯片供应商还是应用开发人员）的一个关键优势在于存在一套完整的开发工具（编译器、运行时库、调试器等），这些工具可以在多个供应商之间重用。

ARM 还在积极致力于在微控制器供应商之间标准化软件基础设施。Cortex 微控制器软件接口标准（Cortex Microcontroller Software Interface Standard, CMSIS）是 Cortex-M 处理器系列的供应商无关的硬件抽象层，并指定了调试器接口。CMSIS 由以下组件组成：

- CMSIS-CORE：Cortex-M 处理器内核和外设的 API。它为 Cortex-M0/0+/3/4/7/23/33 提供标准化接口。
- CMSIS-Driver：定义通用外设驱动程序接口，使中间件可以在受支持的设备之间重用。该 API 与实时操作系统（real-time operating system, RTOS）无关，并将微控制器外设连接到实现通信堆栈、文件系统或图形用户界面等功能的中间件。
- CMSIS-DSP：包含 60 多种函数的 DSP 库集合，适用于各种数据类型：定点（分数 q7, q15, q31）和单精度浮点（32 位）。该库可用于 Cortex-M0、Cortex-M3 和 Cortex-M4。Cortex-M4 实现针对 SIMD 指令集进行了优化。
- CMSIS-RTOS API：实时操作系统的通用 API。它提供标准化的编程接口，可移植到许多 RTOS，因此使软件模板、中间件、库和其他组件能够在受支持的 RTOS 系统之间工作。我们将在第 23 章中讨论这个 API 层。
- CMSIS-Pack：使用名为“PDSC”的基于 XML 的包描述文件，描述文件集合（即“软件包”）中与用户和设备相关的部分，该集合包括源文件、头文件、库文件、文档、闪存编程算法、源代码模板和示例项目。开发工具和 Web 基础设施使用 PDSC 文件提取设备参数、软件组件和评估板配置。

<!-- page: 50 -->

- CMSIS-SVD：外设的系统视图描述（System View Description, SVD）。在 XML 文件中描述设备的外设，可用于在调试器中创建外设感知，或创建包含外设寄存器和中断定义的头文件。
- CMSIS-DAP：调试访问端口（Debug Access Port）。连接至 CoreSight 调试访问端口的调试单元的标准固件。CMSIS-DAP 作为单独的包分发，非常适合集成在评估板上。
- CMSIS-NN：神经网络。由于最新 Cortex-M4/7 内核计算能力的提升，基于神经网络的解决方案即使在嵌入式机器学习应用中也越来越流行。CMSIS-NN 是一组高效的神经网络内核，旨在最大化 Cortex-M 处理器内核上神经网络的性能并最小化其内存占用。

然而，ARM 的这一举措正在自行演进，并且主要与 ARM Keil 工具链的演进相关。对 ST 所有组件的支持仍然局限于某些 API，我们将在后续章节中看到。官方 ST HAL 是开发 STM32 平台应用程序的主要方式，而不同系列的微控制器（MCU）之间存在许多特殊性。此外，很明显，芯片供应商的主要目标是留住客户，并避免他们迁移到其他 MCU 平台（即使基于相同的 ARM Cortex 内核）。因此，我们距离拥有一个完整且可移植的、适用于市场上所有基于 ARM 的 MCU 的层还相去甚远。

## 1.2 STM32 微控制器简介

STM32 是一个广泛的微控制器系列，分为十七个子系列，每个子系列都有其独特的特性。ST 于 2007 年开始该系列的市场生产，从 STM32F1 系列开始，该系列目前仍在生产中。图 1.12 展示了 STM32F103 MCU 的内部芯片裸片（die），这是最广泛使用的 STM32 MCU 之一¹²。所有 STM32 微控制器都具有一个 Cortex-M 内核，以及一些独特的 ST 特性（如 ARTTM 加速器）。内部而言，每个微控制器由处理器内核、静态 RAM、闪存存储器、调试接口以及各种其他外设组成。一些 MCU 提供额外的内存类型（EEPROM、CCM 等），并且针对低功耗应用的整个设备产品线也在不断增长。

### 1.2.1 STM32 产品组合的优势……

STM32 平台为嵌入式开发人员提供了多项优势。本段试图总结其中相关的主要优势。

- 它们是基于 Cortex-M 的 MCU：对于刚接触该平台的人来说，这一点可能还不是很清楚。作为基于 Cortex-M 的微控制器，这确保了市场上有多种工具可用于开发您的应用程序。ARM 已成为嵌入式世界的一种标准（这在 Cortex-A 处理器中尤为真实；在 Cortex-M 市场细分中，仍有几个优秀的替代方案：PIC、MSP430 等），并且到 2020 年已售出 1600 亿台设备，这有力地证明了投资该平台是一个不错的选择。
- 免费的基于 ARM 的工具链：得益于基于 ARM 的处理器普及，可以使用完全免费的工具链进行工作，无需投入大量资金即可开始使用该平台，这对于爱好者或学生来说极其重要。
- 知识复用：STM32 是一个相当庞大的产品组合，基于一个共同点：其主要 CPU 平台。这确保了，例如，在

- 针对特定 STM32Fx CPU 工作时获得的知识可以轻松地应用于同一系列的其他设备。此外，使用 Cortex-M 处理器允许您在（或您的采购团队）决定切换到其他供应商的 Cortex-M MCU 时（理论上）复用大部分已获得的技能。
- 官方开发环境：近年来，ST 在构建完整的开发环境方面投入了大量精力。过去他们犯了很多错误，资助了几个最终一无所成的项目。CooCox IDE 和 SW4STM32 是 ST 之前试图支持开源社区为其微控制器构建完整工具链的两次尝试，但都以惨败告终。最终，ST 意识到这阻碍了很多人采用 STM32 产品组合，因此他们决定收购 Atollic，以便将其 TrueSTUDIO IDE 用作 STM32 微控制器系列的官方工具链。

- 集成引导加载程序：STM32 MCU 出厂时带有集成引导加载程序，允许使用某些通信外设（USART、I²C 等）重新编程内部闪存存储器。对你们中的一些人来说，这可能不是一个杀手级特性，但它可以极大地简化专业设备开发人员的工作。

### 1.2.2 …及其缺点

本书不是宣传册，也不是由营销人员编写的文档。作者也不是 ST 的员工，或与 ST 有业务往来。因此，可以说该平台存在一些陷阱。

- 学习曲线：STM32 的学习曲线可能相当陡峭，尤其是对经验不足的用户而言。如果你完全新手于嵌入式开发，学习如何开发 STM32 应用的过程可能会令人沮丧。尽管 ST 在努力改善整体文档和官方库方面做得很好，但处理该平台仍然很困难，这很遗憾。历史上，ST 的文档对于经验不足的人来说并不是最好的，过于晦涩且缺乏清晰的示例。

¹³由于 2020 年代的硅片市场危机，这一口号不再有效。IC 行业的疯狂状况导致低成本 IC（受影响最大的部分）价格上涨超过 25%。然而，祸不单行，对于低成本应用，STM32F0 系列仍然是一个值得评估的系列，除非 8 位解决方案适合你。

- 文档碎片化且分散：ST 正在积极改进 STM32 平台的官方文档。你可以在 ST 网站上找到许多巨大的数据手册，但对于其 HAL 来说，仍然缺乏良好的文档。CubeHAL 的近期版本提供了一或多个“CHM”文件¹⁴，这些文件是从 CubeHAL 源代码中的文档自动生成的。然而，这些文件不足以开始使用该框架进行编程，尤其是如果你对 STM32 生态系统和 Cortex-M 世界是新手。
- 存在缺陷且性能不佳的 HAL：坦率地说，ST 的官方 HAL 多年来有了很大改进，但它仍在演变中，并且在 HAL 的高级和较少普及的模块中，发现一些严重缺陷是很常见的，就像作者在使用 HAL_PCD 模块时遇到的情况一样（我花了两个月时间识别出一个影响 STM32L052 MCU 上 USB HAL 库的棘手缺陷）。ST 正在积极修复 HAL 缺陷，但似乎距离“稳定版本”还很远。此外，他们的软件发布生命周期过于陈旧，不适合我们生活的时代：缺陷修复在几个月后发布，有时修复本身带来的问题比损坏的代码更多。最后，CubeHAL 远不能被认为是一个优化的库。HAL 被设计为从底层家族和特定 MCU 中抽象出来，这要求 HAL 例程充满 if-then-else 语句。对于时间关键型应用，ST 发布了 CubeHAL-LL 库，这本质上是一组宏，用于简化外设寄存器的操作。再次提醒，你是飞行员，你必须驾驭所有这些工具。

主流 MCU 是为成本敏感型应用开发的，其中 MCU 的成本必须低于 1 美元/件，且空间是一个强约束。在该组中，我们可以找到基于 Cortex-M0/0+/3/4 的 MCU，最大时钟频率范围从 48MHz (F0) 到超过 170MHz (G4)。

超低功耗组包含那些针对低功耗应用的 STM32 MCU 家族，用于需要降低总功耗以确保更长电池寿命的电池供电设备。在该组中，我们可以找到基于 Cortex-M0+ 的 MCU，用于成本敏感型应用，以及基于 Cortex-M4F 的微控制器，具有动态电压缩放 (DVS)，这是一种允许根据频率优化内部 CPU 电压的技术。此外，ST 最近在该类别中也引入了具有新 Cortex-M33 内核的 MCU，专为安全是强约束的应用设计。该组的 MCU 范围从 32MHz Cortex-M0+ 到 160MHz Cortex-M33。

### 1.3.14 G0

![Image from PDF page 75](../images/page-0075-image-01.png)

表 1.17：STM32G0 特性

2019 年，ST 向市场推出了 STM32F0 系列的现代化替代品：STM32G0 系列。该新系列基于 90nm 光刻工艺，而非 STM32F0 系列所使用的较旧的 180nm 工艺。这意味着在相同外设下所需的空间更小、封装更小、由于对硅片需求降低而在大批量生产时成本更低、功耗更低。传统上，与其他提供 SO-8 等更小封装的 Cortex-M 制造商相比，STM32 微控制器（MCU）通常采用较大的封装。如今，ST 终于弥补了这一差距，允许减少 PCB 空间和设计复杂度。事实上，STM32G0 不再使用传统的多条电源线路及其必要的去耦电容，而是仅使用一条电源线路，这将使 PCB 设计变得更加简单且成本更低。这也意味着，与具有相似引脚数量的相应 STM32F0 微控制器相比，某些 STM32G0 微控制器提供了多出的九个 I/O。此外，STM32G03X 和 STM32G04X 微控制器在小封装（SO8、TSSOP20）中采用了多键合（multi-bonding）方法，以提供最多的复用功能和模拟输入。这种方法导致多个芯片焊盘在内部连接到单个封装引脚。

这一代新产品提供了 64 MHz 的 Cortex-M0+ 内核、可保护内存区域（Securable Memory Area）、更多的 RAM 和 Flash、更多的 I/O，以及更广泛的组件集成，从而显著简化了整体 PCB 设计。32 引脚和 48 引脚型号从最简单的配置（8 KB RAM 和 16 KB Flash）到最强大的架构（128 KB RAM / 512 KB Flash）。采用 Cortex-M0+ 内核将有助于在低功耗模式下进行应用程序编程。尽管是一款主流设备，但得益于与 STM32L4 具有某些相似之处的 90nm 工艺，STM32G0 在 64 MHz 运行时所需的电流低于 100 µA / MHz。相比之下，STM32F0 需要 250 µA / MHz。新架构还具有一种 STOP 模式，在仅关闭 Flash 和实时时钟（Real-Time Clock）的情况下，电流可低至 3 µA；而其 STANDBY 模式仅需 200 nA，这比上一代产品的任何模式都大幅降低。尽管处于如此低的功耗状态，该架构仍能在 STOP 模式下约 5 µs 内、在 STANDBY 模式下约 14 µs 内唤醒，使其更具优势。

此外，STM32G0 提供了一个 VBAT 引脚，这意味着工程师可以放置一个电容仅为 RTC 和备份寄存器（backup registers）供电，从而允许系统的其余部分关闭，并将

<!-- page: 76 -->

功耗降低至 10 nA。凭借如此低的功耗，可以创建一种设计，在用户更换电池时保持内存中的基本信息，例如，从而改善整体体验。

最后，STM32G0 包含一个能够加速 AES 256 位计算的加密内核（crypto-core），以及一个用于优化加密密钥的真随机数生成器（True Random Number Generator, TRNG）。然而，最有趣的安全特性是可保护内存区域（securable memory area）的实现。开发人员可以定义 Flash 的一部分，一旦从中注销，该部分将对系统的其余部分不可访问，这使得他们能够存储根密钥和关键例程，以实现安全启动（Secure Boot）和安全固件升级（Secure Firmware Upgrade）等功能。

STM32G4 是首个配备两个数学加速器的 STM32，一个用于三角计算（ST 称之为 COordinate Rotation DIgital Computer 或 CORDIC），另一个用于滤波功能（ST 称之为 Filter Mathematical ACcelerator 或 FMAC）。简单来说，CORDIC 加速器为电机控制、计量、信号处理以及许多其他应用中常见的三角函数提供硬件加速。另一方面，FMAC 使得能够实现信号处理中的两种主要初级滤波器：有限冲激响应（FIR）和无限冲激响应（IIR）数字滤波器。STM32G4 系列也是首个包含分辨率低于 200 皮秒定时器的 ST MCU 架构。其首要且最明显的优势是能够驱动 LLC 谐振拓扑中的高精度电源。该定时器还通过七个时基（timebases）的存在，提供了高度灵活的脉冲宽度调制（PWM），开发人员可以组合这些时基以获得非常精细的调制。高分辨率定时器还受益于一个事件处理器（event handler），帮助工程师更轻松地配置和调用定时器，或例如使用它来生成中断。

STM32G47x 微控制器还具有一个关键特性，即双 Bank Flash，类似于某些 STM32F4 以及所有 STM32F7/H7 系列。简单来说，MCU 将 Flash 内存组织为两个具有边读边写（Read While Write, RWW）能力的物理 Bank。因此，可以在没有任何中断的情况下下载、安装并运行新固件。系统在一个 Bank 上运行，而另一个 Bank 接收新固件。然后，系统可以热切换（hot swap）Bank，并无缝切换到第二个 Bank 以运行新代码。开发人员甚至可以使用 STM32G4 上可用的新安全特性（如可保护内存区域）来保护下载操作：可保护内存区域是内存的一个部分，可以存储秘密密钥或执行软件例程，并且仅在复位后运行一次，之后对用户代码不可见。此外，STM32G4 还借用了 STM32F3 中可用的其他特性，如本书后文描述的核耦合内存（Core Coupled Memory, CCM）。

### 1.3.18 如何为您选择合适的 MCU？

为新项目选择微控制器绝非易事，除非您正在复用之前的设计。首先，市场上有数十家 MCU 制造商，每家都有自己的市场份额和目标受众。例如 ST、Microchip、TI、Atmel、Renesas、NXP 等¹⁸。就我们而言，我们非常幸运：我们已经选定了一个品牌。正如前几段所述，STM32 确实是一个庞大的产品组合。我们可以从超过 1200 种器件中进行选择（如果考虑封装变体的话）。那么，从哪里开始呢？

在理想世界中，选择过程的第一步是理解所需的计算能力。如果我们打算开发一个 CPU 密集型应用，专注于多媒体和图形应用，那么我们必须将注意力转向 STM32 微控制器的高性能（High-Performance）组。另一方面，如果计算能力不是我们电子设备的主要需求，我们可以专注于主流（Mainstream）细分市场，并仔细查看提供最多选择范围的 STM32F1 系列。

下一步是关于连接性要求。如果我们需要通过以太网连接或其他工业协议（如 CAN 总线）与外部世界交互，并且我们的应用程序必须具有响应能力并能够处理多种互联网协议，那么 STM32F4 产品组合可能是您的最佳选择；否则，STM32F105/7 连接性产品线是更好的选择。

如果我们打算开发一个电池供电的设备（也许是可穿戴市场上的下一个畅销产品），那么我们必须查看 STM32L 选择，并根据我们所需的计算能力在各种子系列中进行选择。

如本段开头所述，这是理想世界中的选择过程。但现实世界呢？在日常开发过程中，在开始为项目选择合适的 MCU 之前，我们可能必须回答以下问题：

- 该设备是面向大众市场还是利基市场？如果您正在开发一种小批量生产的设备，那么 STM32 微控制器之间的价格差异不会对您的项目产生太大影响。您甚至可以考虑全新的 STM32F7，并对软件优化给予较少的关注（在处理低性能 MCU 时，您必须尽力优化代码——请记住，这也是一种增加最终投资的成本）。另一方面，如果您打算构建大众市场设备，那么单个 IC 的价格确实很重要：您在生产过程中节省的费用往往超过初始投资。
- 总 BOM（物料清单）的允许预算是多少？这是前一点的一个推论。如果您已经有了目标板的价格，那么您必须在早期阶段仔细选择合适的 MCU。
- 空间限制如何？您的板子是否必须适合最新的可穿戴设备，或者您是否有足够的空间使用您偏好的 IC 封装？这个问题的答案深刻地

ST 在 2015 年推出了一系列全新的开发板：Nucleo。Nucleo 系列分为三个主要组别：Nucleo-32、Nucleo-64 和 Nucleo-144（见图 1.18）。每个组别的名称源自所使用的微控制器（MCU）封装类型：Nucleo-32 使用 LQFP-32 封装的 STM32；Nucleo-64 使用 LQFP-64 封装；Nucleo-144 使用 LQFP-144 封装。Nucleo-64 是首个推向市场的系列，目前共有 32 种不同的开发板，每块板都配备特定的 STM32 微控制器。Nucleo-144 于 2016 年 1 月推出，是首个配备强大 STM32F746 的低成本套件。它还提供了以太网物理层收发器²²和 LAN 端口。由于 Nucleo-64 是最完整的系列，本书将仅涵盖 Nucleo-64 系列中最相关的开发板（完整列表见表 1.21）。在本书的其余部分，我们将简单地用术语“Nucleo”来指代 Nucleo-64。

Nucleo 由两部分组成，如图 1.19 所示。带有 mini-USB 连接器的部分是一个集成的 ST-LINK 2.1 调试器，用于将固件上传到目标微控制器（MCU）并进行单步调试。ST-LINK 接口还提供虚拟 COM 端口（VCP），可用于与主机 PC 交换数据和消息。Nucleo 开发板的一个关键特性是，ST-LINK 接口可以轻松地从板子的其余部分分离出来（图 1.19 中的两个红色剪刀图标指示了断开位置）。这样，它可以作为独立的 ST-LINK 编程器使用（独立的 ST-LINK 编程器价格约为 25 美元）。然而，ST-LINK 提供了一个可选的 SWD 接口，可以通过移除标有 ST-LINK 的两个跳线帽，在不将 ST-LINK 接口从 Nucleo 上拆下的情况下（正如在 Discovery 开发板上已经发生的那样）用于编程另一块板子。板子的其余部分包含目标微控制器（MCU）（我们将用于开发应用程序的微控制器）、一个 RESET 按钮（黑色）、一个用户可编程的轻触按钮（蓝色）和一个 LED。板子上还有一个用于安装外部高速晶振（HSE）的焊盘。所有较新的 Nucleo 开发板都已提供低速晶振。最后，板子上有几个引脚排针，我们稍后会详细介绍。

## 为什么选择 Nucleo 作为本书的示例开发板？

![Image from PDF page 89](../images/page-0089-image-02.png)

这个问题的答案几乎都包含在前面的段落中。首先，Nucleo 开发板价格低廉，让您几乎零成本地开始学习 STM32 平台。其次，它们极大地简化了本书中包含的说明和示例。您可以完全自由选择您喜欢的 Nucleo 开发板。本书将展示所有必要的步骤，以便轻松地将示例适配到您特定的 Nucleo 开发板上。

请记住，整本书的设计旨在为读者提供开始使用任何开发板（即使是定制开发板）所需的所有必要工具。将示例适配到您的具体需求将变得轻而易举。
