# 28. 开始新设计

如果你在工作中使用 STM32 微控制器，或者你作为一名爱好者打算创建你最新的有趣项目，那么迟早你需要离开像 Nucleo 这样的开发套件，并围绕给定的 STM32 MCU 设计一块定制板卡。对于每一位硬件工程师来说，这总是一个令人兴奋的过程。你从一个想法或一份需求列表开始，最终将获得一块能够施展“魔法”的硬件。

新板卡的设计过程可以分为两个主要步骤：硬件设计部分，涉及元器件的选择和布局；以及软件开发部分，包括初始配置以及使板卡正常工作所需的所有代码。本章旨在简要介绍这一主题。本章在逻辑上分为两部分：一部分与硬件设计相关，另一部分与软件相关。即使你是那些幸运的人之一，所在公司的硬件工程师与固件开发人员是分离的角色，也强烈建议你阅读本章，因为本章主要基于硬件设计。否则，如果你是典型的“一人乐队”¹，至少阅读一次本章可能会对你有所帮助，特别是如果你对 STM32 世界完全陌生的话。

## 28.1 硬件设计

如果你来自更简单的微控制器架构，例如用于 Arduino UNO 的 ATMEL AVR ATMega328p，你可能熟悉网络上经常出现的一些“艺术性事物”（图 28.1 是一个例子²）。许多项目起源于面包板、少量无源元件和几吨电线。而且它们工作得非常好。

然而，如果你打算使用 STM32 MCU 制作一块新板卡，你必须完全忘记这种类型的设计。这是因为不仅不存在提供 THT（通孔插装）封装的 STM32 微控制器。这些 MCU 要求在 PCB 布局过程中给予特别关注，即使是低成本系列的 STM32F030 也是如此。如果你计划使用最快的 STM32 MCU，例如 F4 和 F7 系列，并结合外部设备如高速 QSPI 存储器和外部 SDRAM，那么 PCB 设计变得至关重要。

### 28.1.1 PCB 层叠结构

每次你开始基于微控制器的新设计时，你需要决定哪种 PCB 技术最适合你的设计和 BOM 成本，同时牢记这一重要公理：你的板卡速度越快，所需的 PCB 层数就越多。这对于 STM32 MCU 也是如此。虽然并不罕见看到一些低成本 8 位 MCU 焊接在单层 CEM PCB⁴ 上，但对于 STM32 MCU，2 层板卡是最低要求。但是，如果你计划使用 STM32F4 系列的最快版本（如能够运行高达 180MHz 的 STM32F446 MCU）或最新的 STM32H7 系列，那么你必须考虑 4 层 PCB 作为最低要求⁵。

多层 PCB 与 2 层 PCB 相比有几个优势：

- 更多的层简化了布线过程，如果你有空间限制或需要布线差分对网络，这一点非常重要。
- 它们允许更好地布线电源和地连接；如果电源也位于一个平面上，只需添加过孔即可在电路的所有点获得电源。

³http://bit.ly/1NVb6ly ⁴这对于低成本生产尤其如此。 ⁵考虑到 STM32F746-Discovery KIT 是使用 8 层 PCB 制作的。

<!-- page: 874 -->

- 它们在电源平面和地平面之间提供固有的分布电容，减少高频噪声，特别是如果你的板卡依赖于外部 SRAM 或高速闪存。
- 出于与之前相同的原因，它们允许显著减少 EMI/RFI 发射，简化开发成本和 CE/FCC 认证阶段。

然而，与 2 层 PCB 相比，4 层 PCB 的成本更高，而且这种成本对于某些低成本和高产量的生产来说往往是不可承受的。此外，可以说 Cortex-M 组合（因此也是 STM32 组合）的范围从能够在 2 层板卡上正确运行的“低成本”解决方案，到更接近通用微处理器（如 Cortex-M7 系列）的更强大的 MCU，后者需要更先进的 PCB 层叠结构。

我的个人经验基于使用 STM32F030 和 STM32F401 MCU 设计的 PCB，两者都采用 2 层 PCB 实现，并且在板卡测试期间我没有遇到重大问题。在两层上使用地平面可以简化布线过程并减少板卡的整体 EMI 发射。

### 28.1.2 MCU 封装

微控制器（MCU）的封装选择通常与整个 PCB 工艺相关。STM32 微控制器提供多种封装变体。最常见且“易于使用”的封装是 LQFP 封装，例如所有 Nucleo 开发板所使用的 LQFP-64 封装。具有外露引脚的封装具有以下几个优点：

- 它们易于焊接，即使是低批量生产或原型制作也可以手工完成。经过少量练习，可以使用拖焊技术⁶进行焊接，或者简单地使用模板将元件放置在预先涂有焊膏的 PCB 上。
- 它们易于使用传统的自动光学检测（AOI）机器进行检查，并且不需要 X 射线检测，后者会增加你板子的生产成本。
- 与其他类型的封装相比，它们在低批量和中批量生产中成本更低。
- 它们可以用于 2 层低等级 PCB（即使图案等级等于 6 也足够⁷），而其他封装（如 BGA 封装）通常由于使用了环宽减小的过孔，需要更先进的 PCB。
- 它们提供了大量的信号 I/O，用于连接外部外设（这显然是显而易见的，但总是值得强调的）。

然而，如果空间是你设计中的严格限制条件，那么你必须考虑 BGA 及类似封装，它们在更小的占板面积内提供更多的信号 I/O。

### 28.1.3 电源引脚的去耦

一个重要的设计步骤是对每个电源对（VDD, VSS）进行去耦。关键要点可以总结如下：

- 每个电源对（VDD, VSS）应连接一个约 100nF 的并联陶瓷电容（这是一个广泛验证过的值），外加一个 4.7µF 的陶瓷电容用于整个 MCU。最好选择 0805 或更小的电容（越小越好，因为较小的电容具有更低的 ESR - 对于 STM32F7，0402 电容是一个值得考虑的选项）。这些电容需要尽可能靠近相应的引脚放置，或者如果使用 BGA 封装用于最快的 STM32 微控制器，则放置在 PCB 的底部。如果使用地平面，当该引脚周围有广泛的地平面时，可以安全地将 VSS 引脚直接连接到地平面。
- 本作者还在距离芯片不超过 3cm 的地方使用一个大电解电容（通常是 10µF - 如果预算允许，钽电容也可以）。这个电容的目的是作为电荷储备，以供应电路局部的瞬时电荷需求，从而无需通过电源走线的电感来获取电荷。
- 在模拟电源（AVDD）和数字电源（VDD）之间串联放置一个小铁氧体磁珠（阻抗范围从 600 到 1000Ω）⁸。它用于：

- – 将系统中的噪声局部化。 – 防止外部高频噪声进入 IC。 – 防止内部产生的噪声传播到系统的其余部分。
- 如果你的 STM32 微控制器提供 VBAT 引脚，它可以连接到外部电池（1.65 V < VBAT < 3.6 V）。如果没有使用外部电池，建议将此引脚通过一个 100nF 的外部陶瓷去耦电容连接到 VDD。

### 28.1.4 时钟

如果你的设计需要外部时钟源，无论是 LSE 还是 HSE，都必须特别注意外部晶体的位置以及用于匹配其负载电容的电容选择（该值由晶体制造商确定，并在选择过程中必须仔细检查）。

ST 提供了一份关于振荡器设计的非常出色的指南（AN2867¹¹）。总结该指南超出了本段落的范围，因此我强烈建议查看该应用笔记。然而，强调以下几点很重要。

大多数启动错误（即当使用外部晶体时，MCU 在我们的最终设计中无法正确启动）源于外部电容选择错误和晶体放置不当。例如，假设杂散电容等于 5pF，晶体电容等于 15pF，可以使用以下公式计算外部电容的值：

C1,2 = 2(CL - Cstray) = 2(15pF - 5pF) = 20pF.

此外，最好将晶体尽可能靠近 MCU 引脚放置，并用一个独立的地平面包围它，该地平面再连接到底部地平面，如图 28.4 所示（未显示底部地平面）。

ST 在其应用笔记中展示了几个“错误示例”。此外，所有 STM32 微控制器都提供了一个有用的功能来调试外部振荡器问题：时钟安全系统（CSS）。CSS 是一个自诊断外设，用于检测 HSE 故障。如果发生这种情况，HSE 会自动禁用（这意味着内部 HSI 会自动启用），并触发一个 NMI 中断，以通知软件 HSE 存在问题。因此，如果你的板子拒绝正常工作，我强烈建议你编写 NMI 的异常处理程序，如第 10 章所述。如果代码在其中挂起，那么你的振荡器设计存在问题。

最后，请注意，许多 EMC 问题源于外部时钟放置不当。请留意 ST 应用笔记中包含的说明。

### 28.1.5 RESET 引脚的滤波

为了避免板子发生非预期的复位，强烈建议在 RESET 引脚（名为 NRST）和地之间连接一个去耦电容（100nF 是经过验证的有效值），即使您的设计不需要使用复位引脚。

### 28.1.6 调试端口

为了开发和新板子的固件测试，或者简单地将其上传到生产设备，您需要一种通过其调试端口与目标 STM32 微控制器交互的方式。STM32 微控制器提供了多种调试方式。其中一种是通过使用串行线调试（Serial Wire Debug, SWD）接口。SWD 取代了传统的 JTAG 端口，使用一条时钟线（名为 SWDCLK）和一个单双向数据引脚（名为 SWDIO¹²），提供所有正常的 JTAG 调试和测试功能，并且可以在不停止处理器或不要求目标驻留代码的情况下实时访问系统内存（实现此功能的条件是 SWD 相关的 I/O 未被重映射到其他功能 - 例如，通用输入/输出 GPIO）。此外，可以使用任何 ST-LINK 调试器作为您自定义板子的调试设备：所有 ST 开发板（因此也包括 Nucleo）都是

### 28.1.7 启动模式

根据您在设计中将要使用的特定微控制器型号，STM32 微控制器可以从不同的源加载固件：内部或外部闪存、内部或外部 SDRAM、USART 和 USB 是启动固件执行的最常见源。这是在第 22 章中描述的该平台的令人兴奋的功能。

这之所以可能，是因为在微控制器生产过程中，多个启动加载器被预编程在系统内存中（从 0x1FFF F000 开始的代码区域子区域）。每个启动加载器都可以通过配置名为 BOOT0 和 BOOT1¹³ 的一个或两个引脚来选择。

默认行为，即从内部闪存正常启动，是通过将至少 BOOT0 引脚拉低到地，并让 BOOT1 引脚（如果存在）悬空来实现的。一旦固件开始执行，您可以将 BOOT 引脚重新用作通用 I/O。

¹³这些引脚的实际实现取决于特定的 STM32 系列。例如，STM32F030 仅提供 BOOT0 引脚，并用选项字节内存区域中的一个特定位取代 BOOT1 引脚。

### 28.1.8 注意“引脚对引脚”兼容性……

许多 STM32 微控制器被设计为与同系列中的其他 MCU 以及不同系列之间的 MCU 具有引脚对引脚（pin-to-pin）兼容性。这允许您在需要因预算原因调整设计或寻找更强大的 MCU 时，“简单地”切换到性能更高或更低的型号。

然而，引脚对引脚兼容性是一个需要在 MCU 选择过程中进行规划的特性，即使对于属于同一 STM32 系列的 MCU 也是如此。让我们考虑这个例子¹⁴。假设您决定使用 STM32F030 目录中的 STM32 MCU，并且您选择了 STM32F030R8 MCU，即配备在 STM32F030 Nucleo 上的那个。一旦板级设计完成，gerber 文件被发送到 PCB 制造商，您就开始开发固件（这种情况经常发生，特别是如果您必须在开始开发前一天完成项目的话）。过了一段时间，您发现该 MCU 提供的 8k SRAM 对于您的项目来说是不够的。因此，您决定切换到 STM32F030RC 型号，它提供 32K SRAM 和 256K 内部闪存。然而，在挣扎了几个小时后试图理解为什么无法烧录它时，您发现该型号需要四个额外的电源引脚（PF4, PF5, PF6 和 PF7），如图 28.7 所示。

### 28.1.9 ……以及选择正确的外设

大多数 STM32 MCU 具有多个给定类型的外设（SPI1, SPI2 等）。对于具有多个模块的复杂设计来说，这是一件好事，但在选择外设时必须格外小心，即使是简单的设计也是如此。而且，这不仅仅是与 I/O 分配相关的问题。例如，让我们假设您的设计基于 STM32F030 MCU，并且假设您的设计需要一个 UART 和一个 SPI 接口。您决定使用 UART1 和 SPI2 外设。在固件开发过程中，出于性能原因，您决定将两者都设置为 DMA 模式。然而，查看表 9.2 后，您会发现不允许同时以 DMA 模式使用 SPI2_TX 和 USART1_RX（它们共享同一个通道）。因此，最好在绘制原理图时规划这些软件设计选择。

如果您正在设计一个将进入更深睡眠模式（如待机模式）的设备，并且希望设备能被用户唤醒（例如通过按下专用按钮），请记住通常只有两个 I/O 可用于此任务（它们被称为唤醒引脚）。因此，避免将这些引脚分配给其他用途。

### 28.1.10 CubeMX 在板级设计阶段的作用

有时，我会和别人谈论 CubeMX。很多人对 CubeMX 是什么有错误的看法。有些人认为它完全没用。其他人将其使用限制在软件开发阶段。这完全错了。

<!-- page: 883 -->

CubeMX 可能在硬件设计过程（无论是绘制原理图还是进行板级布局）中比在固件开发阶段更有用。一旦您熟悉了 CubeHAL，您将不再使用 CubeMX 作为 IDE 项目生成工具¹⁵。但是，除非您打算重用之前的设计或始终基于少数几种 STM32 MCU 类型构建项目，否则 CubeMX 在设计阶段是必不可少的。

默认情况下，Release 配置的 GCC 优化级别为 -Os。更高的优化级别会对程序执行更多的全局转换，并应用更昂贵的分析算法，以生成更快且更紧凑的代码。然而，在嵌入式编程中，通常建议从无优化（-O0）级别开始开发。这是因为更激进的优化可能会导致受时间约束的例程出现不同的行为。作为经验法则，请使用 -O0 或 -Og 级别开发固件，并在测试其所有功能的同时逐步提高优化级别。有时，使用 -O0 级别编译时运行完美的固件，在选择更激进的优化后可能会完全停止工作。这通常发生在我们未正确地将共享变量和全局变量声明为 volatile 时，导致它们被编译器优化，从而引起 ISR 例程或在使用实时操作系统（RTOS）时的不同线程出现错误行为。

Release 配置的另一个重要配置参数与调试级别（Debug level）相关。此功能在 Cross ARM C++ Compiler->Debugging 视图中进行配置，GCC 提供四个递增的级别：None、-g1、-g（Release 配置中的默认值）和 -g3。如果您想生成不包含调试信息的二进制映像，请选择 None 级别。

## 从固件强制 MCU 复位

有时，当一切失控且我们无法再控制正在发生的事情时，唯一的解决办法是复位微控制器。函数

```text
void HAL_NVIC_SystemReset(void);
```

启动 MCU 的系统复位。它使用了由 CMSIS 包提供的 void NVIC_SystemReset(void)。

## STM32 96 位唯一 CPU ID

大多数 STM32 微控制器都提供了一个唯一的 CPU ID，该 ID 在出厂时已编程写入。它是只读的，且无法更改。

此 ID 在多种上下文中可能很有用。例如，它可以用于：

- 作为唯一的 USB 设备序列号；
- 生成自定义许可证密钥；
- 用作安全密钥，以结合软件加密原语和协议，在编程内部 Flash 存储器之前提高 Flash 存储器中代码的安全性；
- 激活安全启动过程等。

不幸的是，此 ID 在内存中的位置并非所有 STM32 微控制器通用，其内存映射地址在不同的 STM32 系列之间有所变化。表 1 显示了配备 Nucleo 开发板的 MCU 的唯一 MCU ID 的内存映射地址。

## STM32 相关问题

本节列出了与 STM32 微控制器编程相关的常见问题。

### 微控制器无法正确启动

虽然这看起来可能很奇怪，但 STM32 拒绝正常启动的原因列表相当长。此问题通常具有以下症状：

- 固件未启动。
- 程序计数器（Program Counter）指向一个完全无效的地址（通常是 0xfffffffd 或 0xfffffffe，但也可能是 4GB 内存空间中的其他地址），这在 Eclipse 的调试会话中可以看到。

<!-- page: 895 -->

![Image from PDF page 895](../images/page-0895-image-01.jpeg)

要解决此问题，我们需要区分两种情况：如果您正在为 Nucleo 等开发板或自定义设计的板卡开发固件（这种区别只是为了简化分析）。

如果您正在使用开发板开发固件，尤其是如果您是新接触该平台（但即使是经验丰富的用户，疲劳也可能导致失误……），可能有两件事出错了：

- 链接脚本 STM32XXXXXX_FLASH.ld 文件中内存区域的定义是错误的，无论是闪存（flash）区域还是 SRAM 区域（通常，闪存区域没有从 0x08000000 开始）。
- 启动文件（startup file）已损坏。

相反，如果您正在为自定义板卡开发固件，除了检查上述两点外，您还必须检查：

- BOOT 引脚的配置是否正确（至少 BOOT0 引脚接地，BOOT1 引脚悬空）。
- NRST 引脚是否使用 100nF 电容正确去耦。

有时，即使上述所有点都正确，微控制器仍然拒绝启动。这通常在调试会话后，或者在您测试了一个旨在以写模式访问内部闪存内存的有缺陷的固件后突然发生。另一个可识别的症状是 OpenOCD 也无法对 MCU 进行闪存编程。如果是这样，您可能有一个损坏的选项字节（Option bytes）内存区域。STM32CubeProgrammer 可以帮助您调试这种情况。一旦连接了 ST-LINK 调试器，进入选项字节部分，检查 BOOT 配置（在用户配置部分内）是否与您的 MCU 正确匹配。

<!-- page: 896 -->

![Image from PDF page 896](../images/page-0896-image-01.jpeg)

最后，有时完全擦除芯片也可以帮助解决晦涩的启动问题 ;-)

### 无法对 MCU 进行闪存编程或调试

有时会发生无法对 MCU 进行闪存编程或使用调试器进行调试的情况。另一个可识别的症状是 ST-LINK LD1 LED（在板卡处于调试状态时交替闪烁红色和绿色的那个）停止闪烁，并且两个 LED 都保持常亮。

当这种情况发生时，意味着 ST-LINK 调试器无法访问目标 MCU 的调试端口（通过 SWD 接口），或者闪存被锁定，阻止调试器访问。通常有两个原因导致这种故障状态：

- SWD 引脚被配置为通用输入/输出GPIO（如果我们在 CubeMX 中执行引脚配置重置，这种情况经常发生）。
- MCU 处于关闭调试端口的深度低功耗模式。
- 选项字节配置有问题（可能闪存已被写保护或开启了读保护级别 1）。

为了解决此问题，我们必须强制 ST-LINK 调试器在保持其 nRST 引脚低电平的同时连接到目标 MCU。此操作称为复位下连接（connection under reset），可以通过使用 STM32CubeProgrammer 工具，在复位模式（Reset mode）组合框中选择硬件复位（Hardware reset）模式来执行，如下所示。
