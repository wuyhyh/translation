# 27. 通用串行总线

在 20 世纪 90 年代，七家公司¹决定联合力量，定义并标准化一种新的硬件和通信标准，用于将外设互连到主机计算机。该联盟的目标是统一外设与 PC 之间交换数据所使用的硬件介质，同时标准化通信协议。此外，随着外部磁盘驱动器、便携式媒体播放器、数码相机等更快、更强大的外设的出现，市场对更快、更可靠的通信介质的需求日益增加。

二十六年过去了，通用串行总线（Universal Serial Bus, USB）规范依然存在，并且已成为消费电子领域最重要、最普及的行业标准。多年来，USB 实施者论坛（USB Implementers Forum, USB-IF）——即定义所有 USB 相关标准的委员会——发布了多个版本的规范。每一次新版本的发布都带来了更快、更通用的通信标准，以及更便携、更灵活的物理介质和连接器。最初的 USB 1.0 规范允许设计能够以高达 1.5Mbit/s 的带宽交换数据的设备。最新的规范是 2019 年发布的 USB4，支持最高 40Gbit/s 的带宽。

USB 标准在市场中的重要性迫使所有微控制器（microcontroller）供应商在其最先进的设备中采用该标准，ST 公司显然也不例外。所有 STM32 系列都包含多个提供完整硬件支持（至少支持 USB 设备规范）的型号（P/Ns）。此外，ST 免费分发一种 Cube 中间件，简化了开发基于 USB 的应用所需的工作量。

从概念上看，USB 标准并不是一个晦涩且复杂的协议。得益于内部专用的物理层收发器（phythers），STM32 开发人员可以完全忽略协议中所有与硬件相关的方面（如电压信号、消息编码等），而专注于软件部分。然而，当在硬件介质之上实现“逻辑协议”时，事情可能会变得难以掌控。这就是为什么大多数嵌入式程序员和小公司仍然认为 USB 是一个难以学习的协议，他们更倾向于使用 RS-232 等更简单且仍然广泛使用的通信协议。

本章旨在对该主题进行简要介绍。对 USB 规范的完整论述，特别是像 USB 3.0 这样较新的规范，超出了本书的范围，这需要一本页数几乎相当的专门著作。相反，我们将把注意力集中在 USB 2.0 规范的基础主要概念上，并分析 ST 为其 STM32 微控制器设计的中间件结构。

### 27.1.1 USB“临终前”指南

好吧。没有时间浪费了。这是学习 USB 的最后机会。让我们开始吧。

USB 规范有多个版本。最普及的 USB 2.0 支持三种总线速度：480Mbit/s（也称为高速 - High Speed, HS）、12Mbit/s（称为全速 - Full Speed, FS）、1.5Mbit/s（称为低速 - Low Speed, LS）。后两种继承自 USB 1.1 规范。这表明了该标准的另一个重要特性：新版本被设计为向后兼容。

多年来，多种电缆和连接器已被标准化。标准连接器被有意设计为强制 USB 网络的定向拓扑结构：主机设备上的 Type-A 插座提供电源，目标设备上的 Type-B 插座消耗电源。这防止了用户意外地将两个 USB 电源相互连接，这可能导致短路、危险的高电流、电路故障甚至火灾。图 1 展示了七种最普及的 USB 插头和插座。

USB 是以主机为中心的。所有通信都在主机（通常是计算机）和设备之间进行。主机管理线路上的流量，设备响应来自主机的通信。USB 是一个总线。这意味着当主机传输数据包时，该数据包会被发送到连接的所有设备。只有一个设备，即被寻址的设备，会接受数据（其他所有设备都接收它，但由于地址不同，它们会静默地忽略它）。

主机通过“虚拟管道”与设备交换数据包，在 USB 术语中称为端点（endpoint）。每个端点都有一个唯一的地址，并且设备可使用的端点数量有限。这意味着，从总线的角度来看，数据包由目标设备地址加上端点号来标识。从开发人员的角度来看，设备端点是一个存储接收数据或待发送数据的内存缓冲区。除了地址号外，每个端点还具有方向和缓冲区的最大尺寸，后者显然对应于端点在一个事务中可发送或接收的最大数据字节数。一个特殊的端点，称为端点零（EP0），始终存在于 USB 设备中，并由主机用于配置该设备。

每个 USB 传输由一个或多个事务组成，这些事务可以向端点传输数据或从端点接收数据。事务以“令牌包”（token packet）开始，该令牌包指定端点号和传输方向。SETUP 令牌包用于配置整个设备或某些功能。IN 令牌包请求从端点获取数据包。OUT 令牌包跟随来自主机的数据包。除了数据外，每个数据包还包含错误检查位和一个带有数据排序值的包 ID（PID）。许多事务还有一个握手包，其中数据接收者报告事务的成功或失败。为了澄清：我们使用 IN 端点将数据从设备传输到主机，而使用 OUT 端点将数据从主机传输到设备。请记住：USB 是一个以主机为中心的协议。
