### 21.5.1 TCM 存储器在 STM32F7/H7 微控制器中的作用

较新且性能更强的 STM32F7/H7 微控制器的内存组织值得单独提及。事实上，该系列微控制器面临着更复杂、更灵活的内存和总线组织，提供了两种不同的接口来访问闪存（Flash）和 SRAM 存储器：高级可扩展接口（Advanced eXtensible Interface, AXI），这是一种 ARM 总线规范，用于将 CPU 内核与其他外设互连；以及紧耦合存储器（Tightly-Coupled Memory, TCM）接口，用于将 CPU 内核与其直接耦合的易失性和非易失性存储器互连。AXI 和 TCM 这两种接口都采用哈佛架构，为指令（I-Bus）和数据（D-Bus）提供分离的线路。

查看图 21.3¹⁰，可以看到 Cortex-M7 内核有三条不同的路径来访问闪存控制器（从而访问闪存存储器）。在描述这三条路径之前，有必要指出一个基本事实：Cortex-M7 内核已经提供了一个集成的 L1 缓存。该缓存有两个专用的缓存池，每个宽度最高可达 64KB，一个专用于 I-Bus，另一个用于 D-Bus：这与其他 STM32 系列不同，在其他系列中，数据缓存和指令缓存仅在 ART™ 加速器内部实现。

![Image from PDF page 579](../images/page-0579-image-01.jpeg)

图 21.3：STM32F7 微控制器中闪存存储器的访问方式

在所有 STM32F7 微控制器中，闪存存储器可通过三个主要接口进行读取和/或写入访问：

- 64 位 ITCM 接口：它通过 ITCM 总线（图 21.3 中的路径 1）将嵌入式闪存存储器连接到 Cortex-M7，用于程序执行和数据读取

- 以及字面量值的访问。通过此总线不允许对闪存存储器进行写入访问。CPU 可以通过 ITCM 从地址 0x0020 0000 开始访问闪存存储器。由于嵌入式闪存存储器比 CPU 内核慢，ART™ 加速器允许在 STM32F7 中最高 216MHz 的 CPU 频率下，以及在 STM32H7 中最高 480MHz 的 CPU 频率下，从闪存存储器实现 0 等待周期执行。ART™ 加速器仅可用于 ITCM 接口上的闪存存储器访问。它实现了最高 256 位 x 64 行的统一指令和分支缓存。ART™ 加速器可用于指令和数据访问，从而提高了顺序代码和循环的执行速度。ART™ 加速器还实现了指令预取缓冲区。
- 64 位 AHB 接口：它通过 AXI/AHB 桥（图 21.3 中的路径 2）将嵌入式闪存存储器连接到 Cortex-M7。它用于代码执行、读取和写入访问。CPU 可以通过 AXI/AHB 桥从地址 0x0800 0000 开始访问闪存存储器，并且它是可缓存的（即，可以使用 L1 缓存），达到与 ART™ 加速器相同的 0 等待周期性能。Cortex-M7 内核中的 L1 缓存范围可以从 4KB 到 16KB。STM32F7/H7 提供两个缓存池，一个用于指令（I-Bus），一个用于字面量池（D-Bus），每个宽度最高可达 16KB。所有 Cortex-M7 内核上的 L1 缓存都分为 32 字节的行。每行都标记有一个地址。数据缓存是 4 路组相联（每组四行），指令缓存是 2 路组相联。这是一种硬件折衷，以避免必须为每一行标记地址。
- 32 位 AHB 接口：它用于从闪存存储器进行 DMA 传输（图 21.3 中的路径 3）。DMA 对闪存存储器的访问从地址 0x0800 0000 开始执行。

存在第四条路径（见图 21.3），通过高级总线外设（Advanced Bus Peripheral, AHBP）接口，它保留用于访问位于 0x4000 0000 外设映射区域内的闪存外设寄存器。

图 21.4：STM32F7 微控制器中的总线矩阵

这种看似复杂的架构有什么优势？如果两个闪存接口，即 AXI/AHB 和 ITCM，都提供 0 等待周期执行（一个依靠内部 L1 缓存，另一个依靠 ART™ 加速器），为什么我们在固件设计期间要处理这种复杂性？

答案来自 STM32F7 微控制器的总线矩阵架构，如图 21.4¹¹ 所示。如您所见，AXI/AHB 总线通过 AXIM 接口连接到内部 L1 缓存。这意味着对总线上某些外设的访问是可缓存的。FMC 和 QuadSPI 控制器就是这种情况。得益于这种架构，可以使用外部 NVM 存储器来存储数据或程序代码，利用 64K L1 缓存，同时通过 ITCM 接口和 ART™ 加速器对内部闪存存储器进行并行访问（无需总线仲裁）。这对于大量使用存储器来存储图像、视频和一般多媒体内容的设备来说，是一个巨大的性能提升，但也适用于大型常量数据表，如 FFT IV。
