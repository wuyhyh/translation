Table 9.16: M2M transfer test results

The Table 9.16 shows the results obtained for every Nucleo board. Let us focus on the the Nucleo- F401RE board. As you can see, the DMA M2M byte-aligned transfer takes ∼42μS, while the DMA- M2M word-aligned transfer takes ∼14 μS. This is a great speed-up, which proves that using the right DMA configuration can give us the best transfer performance, since we are moving 4 bytes at once for each DMA shoot. What about the memcpy()? As you can see from Table 9.16, it depends on the C library used. The GCC tool-chain we are using provides two C run-time libraries: one is named newlib and one newlib-nano. The first one is the most complete and speed-optimized of the two, while the second one is a reduced-size version. The memcpy() in the newlib library is designed to provide the fastest copy speed, at the expense of code size. It automatically detects word-aligned transfers, and it equals the DMA when doing word-aligned M2M transfers. So, it is much faster than DMA when doing byte-aligned M2M transfers and that is the reason why someone claims that memcpy() is always faster than the DMA. On the other hand, both Cortex-M core and the DMA need to access flash and SRAM memory using the same bus. So, there are no reasons why the MCU core should be faster than the DMA¹⁹. As you can see, the fastest transfer speed is achieved when the DMA stream/channel disables the internal FIFO buffer (∼12 μS). It is important to remark that for STM32 MCUs with smaller flash memories the newlib-nano it is almost an unavoidable choice, unless the code can fit the flash space. But again, using the right DMA settings we can achieve the same performances of the speedoptimized version available in newlib library.
