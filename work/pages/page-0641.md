Now, let us analyze the divide() function storage, considering the diagram in Figure 23.10. The function makes use of three memory locations: two variables will be stored on the function’s stack (x and y), while the errno one will be stored in the .bss section (if this matter sounds new to you, please go back to Chapter 20). Let us assume that the divide() function is called by two different routines running in two separated threads with the same priority. Since every thread has its own TCB and so its stack, the access to local variables is not an issue. Instead, the access to the errno global variable is subject to race conditions. The thread running funcB() could be preempted just before the return instruction at line 11, and the control could be passed to the thread running funcA(), which will set the errno variable to ENOERR: in this case, when the control will go back again to funcB(), the result will be 0 and the caller (that is the funcB()) will assume that the result of division is zero (we are in the integer space, here).
