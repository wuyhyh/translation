### - If your code spawns and kills many tasks during the firmware lifecycle, then it is best to let FreeRTOS to handle memory allocation.

OPTION 4: Mixing newlib and FreeRTOS to Handle Dynamic Memory Allocation This is the “default” CubeMX solution, that needs to be tuned-up to avoid issues. FreeRTOS will have its memory space defined by the global macro configTOTAL_HEAP_SIZE and newlib malloc() will allocate the dynamic memory inside the free space ranging from _Min_Stack_Size and _ebss. The STM’s _sbrk() implementation is not that different from the one provided by Dave Nadler, and we do not need to change it. Instead, we need to ensure thread safety of malloc() routine by providing __malloc_lock()/__malloc_unlock() hooks. The following one is a possible and more complete implementation for the _sbrk() routine.
