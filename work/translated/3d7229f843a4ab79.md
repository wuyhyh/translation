<!-- page: 797 -->

USB 2.0 支持四种传输类型：控制（control）、批量（bulk）、等时（isochronous）和中断（interrupt）。在控制传输中，主机向设备发送定义好的请求。当设备连接时，主机使用控制传输从设备请求一系列称为描述符（descriptors）的数据结构。描述符提供了关于设备能力的信息，并帮助主机决定为设备分配哪个驱动程序。控制传输最多包含三个阶段：SETUP、DATA（可选）和 STATUS。SETUP 阶段包含请求。DATA 阶段包含来自主机或设备的数据，具体取决于请求内容。STATUS 阶段包含关于传输成功与否的信息。

其他传输类型没有定义好的阶段，如何定义和使用消息中包含的数据以及如何解释这些数据，取决于高层软件。

批量传输在其他空闲总线上是最快的，但没有保证的时序。打印机和

<!-- page: 798 -->

USB 虚拟 COM 端口（VCP）数据使用批量传输。

等时传输具有保证的时序，但没有纠错功能。流式音频和视频使用这种类型的传输。

中断传输具有保证的最大延迟，即两次事务尝试之间的时间。鼠标和键盘使用中断传输。这里有一个重要的点需要澄清：中断传输与微控制器（microcontroller）的中断（interrupt）没有任何关系。主机和连接设备之间没有专用的中断线。USB 2.0 物理介质仅由两根名为 D+ 和 D- 的线组成，除了 VCC 和 GND 线之外。中断传输使用一个专用的端点（endpoint），该端点被主机不断轮询。这种类型的传输允许向主机发出信号，表明主机必须执行某个操作，具体取决于特定的协议。

USB 规范并未说明应用层传输字节的意义。这一方面由设备类（device classes）和应用协议来要求，这些协议标准化了消息的结构、其含义、使用的端点数量和类型等。USB-IF 标准化了一些相关的类。例如，人机接口设备（Human Interface Device, HID）是专门用于标准化鼠标、键盘、摇杆等设备的类。

所有 USB 设备都有一个描述符层次结构，为主机提供诸如设备是什么、谁制造的、支持哪个版本的 USB、可以配置多少种方式、端点的数量及其类型等信息。更常见的 USB 描述符包括：

- 设备描述符（Device Descriptors）：它们提供设备功能的总体概述。
- 接口描述符（Interface Descriptors）：它们提供给定设备接口功能的描述（例如，在鼠标中，接口描述符提供有关 HID 类的信息）。
- 端点描述符（Endpoint Descriptors）：这些描述符用于描述除端点零以外的端点。主机将使用从这些描述符返回的信息来确定总线的带宽需求。
- 字符串描述符（String Descriptors）：字符串描述符提供人类可读的信息。

这就是全部内容了。我们现在已经是 USB 协议的专家了。或多或少吧。

### 27.1.2 USB 物理架构概述

如前所述，USB 是一种以主机为中心的串行总线协议。在 USB 总线上只能存在一个充当“主设备”的主机，它调度在总线上流动的消息。同一总线上最多可以共存 127 个“从设备”。主机和设备通过专用的透明设备互连，这些设备称为集线器（hubs）。USB 具有分层星型拓扑结构（图 2）。在根层是 USB 主机。所有设备要么直接连接到主机，要么通过集线器连接。根据 USB 规范，USB 主机最多只能支持七层。

基本上，每个主机设备都由两个基本组件组成：主机控制器接口（Host Controller Interface, HCI）和根集线器。主机控制器是一个专用的集成电路（IC），它实现了处理主机和设备之间消息流动所需的所有硬件要求和部分协议逻辑。市场上存在四种主要的“标准化”PC 主机控制器（OHCI、UHCI、EHCI 和 xHCI）。从本文的角度来看，重要的是要知道 HCI 是一个复杂的硬件部分。据我所知，市场上不存在提供 USB 2.0 HCI 的 Cortex-M 微控制器。相反，一些 MCU，如某些 STM32 微控制器，提供了作为 USB FS 主机工作的能力，实现了一组有限的功能。这使得能够开发 USB 主机设备，以接口一些常见且速度不太快的 USB 设备（鼠标、键盘等）。

USB 规范也可以被视为一种分层架构，如图 3 所示。USB 可以分为三个主要层：总线接口、设备和应用层。

总线接口层由硬件控制器表示。PC 集成一个 HCI，而 STM32 MCU 提供一个专用的硬件物理层（phyther），兼容 USB 2.0 规范的信号，外加一个串行接口引擎（Serial Interface Engine, SIE）。SIE 是硬件层的前端，处理 USB 规范中描述的大部分协议。SIE 通常涵盖直到事务级别的信号。它处理的功能包括：

- 数据包识别、事务排序
- SOP、EOP、RESET、RESUME 信号检测/生成
- 时钟/数据分离
- NRZI 数据编码/解码和位填充
- CRC 生成和检查（Token 和 Data）
- 数据包 ID（PID）生成和检查/解码
- 串行-并行/并行-串行转换

设备层对应于 USB 连接中的软件低层部分。它包含一些通用的 USB 功能（例如用于发现设备能力的设备描述符，我们稍后会看到）和特定协议的功能。例如，大容量存储类（Mass Storage Class, MSC）设备实现了所有允许将外部磁盘驱动器接口到 PC 的功能。同时，PC 操作系统（例如 Windows）需要一个专用的“驱动程序”来接口这样的 USB 设备。

应用层实现了使用设备所需的逻辑。从 USB 设备的角度来看，这一层实现了提供特定功能的实际代码。例如，

我们的 MSC 设备可能实现了必要的代码，以便使用 SPI 协议接口 SD 卡，并且对于 PC 来说，它看起来像任何其他 MSC 设备（即外部磁盘）。MSC 协议基本上由 SCSI 命令组成，这些命令需要由应用代码适配到特定的存储器技术设备（Memory Technology Device, MTD）。

USB-IF 还标准化了互连 USB 设备的硬件介质：插头、插座和电缆。图 4 显示了 USB 2.0 电缆的典型结构。由编织物和箔片（加上确保编织物正确接地的排水线）制成的屏蔽层包围电源线和信号线。电源导体用于向设备提供足够的能量。红色线，也称为 VBUS，为所有连接的设备提供恒定的 4.40 - 5.25V 电源。USB 2.0 端设备可以从 USB 线汲取最多 500mA 的电流。较新的 USB 3.x 标准允许提供高达 5A@20V（100W）的电源。
