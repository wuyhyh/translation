## 27.4 调试 USB 设备

开发 USB 设备并非易事，特别是如果你刚接触 USB 协议，你需要一种方法来调试设备与主机之间交换的数据。执行这项繁琐工作主要有两个选项：硬件协议嗅探器和分析仪，以及软件工具。

### 27.4.1 软件嗅探器和分析仪

市面上有多种免费和商业 USB 软件嗅探器。软件分析仪可用于捕获设备数据传输和协议。它们还可以用于向设备发送命令。软件分析仪通过替换主机上的 USB 软件栈来工作。这是监控 USB 流量的必要步骤。因此，软件分析仪在可呈现的信息方面将依赖于主机硬件。软件分析仪有一个重要优势：它们在驱动程序级别显示通信内容，从而有助于理解你的设备与主机操作系统（operating system）的设备驱动程序之间出了什么问题。然而，软件分析仪也有一些缺点。首先，主机如果不作为总线的一部分，就无法监控 USB 流量。这意味着无法观察挂起（suspend）或复位（reset）等状态。此外，根据主机硬件和软件栈的不同，还有一些总线状态是由主机控制器在没有软件参与的情况下处理的。另一个缺点是软件的跨平台可用性。如果软件分析仪仅在 Windows 上运行，那么你就只能调试与 Windows 操作系统的通信。在当今时代，这是一个严重的限制。最后一个缺点与定时有关。软件分析仪的定时精度取决于主机操作系统，这可能会引入不同程度的不准确性。

你可以找到几种 USB 软件嗅探器。Wireshark³³ 是唯一同时支持 Windows、MacOS 和 Linux 的工具。它完全免费，并且在大多数情况下运行良好。然而，如果你刚接触 USB 协议，可能会发现 Wireshark 的输出有点难以解码。也有几种商业和专用软件可用。USB Monitor³⁴（作者过去曾成功使用过）和 USBTrace³⁵ 是两个值得考虑的良好替代方案。

### 27.4.2 USB 硬件分析仪

如果你需要做一些严肃的工作，你需要严肃的工具。相信这位作者：购买一个硬件协议分析仪，你会节省大量时间。硬件协议分析仪是定制制造的硬件部件（主要是一个 FPGA 和一个具备 USB 能力的微控制器（microcontroller）），插入主机和设备之间以监控总线流量。这些设备中的一些甚至具有生成总线流量的能力，如果试图产生特定条件的话。这类设备的价格因制造商、所需的 USB 规范（USB 2.0 与 USB 3.0）以及流量生成能力而异。通常，这些分析仪的价格从几百美元到几千美元不等。

## 27.5 优化 STM32 USB 设备库

让我们清楚地面对现实：STM32 USB 设备库远非一个优化的库。原因很简单：ST 设计了尽可能通用的 USB 库，从非常具体的 STM32 微控制器、给定的 USB 物理层（LS-FS/HS）和 USB 类中抽象出来。此外，它的设计使得每个人只需适应现有代码即可设计自己的类。然而，这使得库中充满了重复的结构和大量的 if-then-else。结果是一个具有相当大 FLASH 和 SRAM 占用的库，在设计你的应用程序时可能会给你带来很多问题。

你可以通过执行以下简单操作，在不破坏库结构的情况下获得更好的结果：

- 如果你要设计一个仅在 Full-Speed 或 High-Speed 模式下工作的设备，那么你可以从库中移除所有与你未考虑的 USB 速度相关的描述符。例如，如果你的设备仅在 FS 模式下工作，那么你可以完全移除以下巨大的数组：

- – USBD_<CLASS>_CfgHSDesc. – USBD_<CLASS>_OtherSpeedCfgDesc.
- 其他描述符可以定义为 const，这样它们就会进入 FLASH 内存而不是 SRAM。这将节省大量 SRAM 内存。在执行此操作时，注释掉文件 usbd_ctlreq.c 中大约在第 436 行和第 441 行的以下行（老实说，我不知道这些行是用于什么目的的……）：
