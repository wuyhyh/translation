#### 1.1.1.8 电源模式

当前电子行业，尤其是移动设备设计领域，主要趋势在于电源管理。将功耗降至最低是所有参与电池供电设备开发的硬件设计师和程序员的主要目标。Cortex-M 处理器提供多个级别的电源管理，可分为两大类：固有特性和用户定义的电源模式。

所谓固有特性，是指在设计 Cortex-M 内核（内核）和整个微控制器（MCU）时定义的与功耗相关的原生能力。例如，Cortex-M0+ 内核仅定义了两个流水线（pipeline）级，以减少指令预取期间的功耗。另一个与电源管理相关的原生行为是 Thumb-2 指令集的高代码密度，这使得开发人员可以选择具有较小闪存存储器的微控制器，从而降低功耗需求。

![Image from PDF page 47](../images/page-0047-image-01.jpeg)

图 1.10：Cortex-M 在不同电源模式下的功耗

传统上，Cortex-M 处理器通过系统控制寄存器（System Control Register, SCR）提供用户定义的电源模式。第一种是运行模式（Run mode）（见图 1.10），此时 CPU 以全功能运行。在运行模式下，功耗取决于时钟频率和使用的外设。睡眠模式（Sleep mode）是可用于降低功耗的第一种低功耗模式。激活后，大多数功能被挂起，CPU 频率降低，其活动减少到唤醒所需的最小程度。在深度睡眠模式（Deep sleep mode）下，所有时钟信号停止，CPU 需要外部事件才能从该状态唤醒。

然而，这些电源模式只是通用模型，它们在实际的微控制器中进一步实现。例如，考虑图 1.11，它显示了 STM32F2 微控制器

#### 1.1.1.9 TrustZoneTM

ARM 最近推出了两款名为 Cortex-M23 和 Cortex-M33 的新 Cortex-M 处理器内核，两者均基于 ARMv8-M 架构。这些新内核继承了一个在大多数 Cortex-A 处理器中已经存在的特性：ARM TrustZoneTM。TrustZoneTM 是一个可选的安全扩展，旨在为广泛的嵌入式应用提供改进系统安全性的基础。TrustZoneTM 技术的概念并不新鲜。处理器可以运行在安全（Secure）和非安全（Non-secure）状态，非安全软件只能访问非安全内存区域。通过操作内存映射（memory map）配置，可以定义内存地址空间中的区域，使得只有当处理器运行在安全模式时，才能访问该区域（无论是执行代码还是访问数据）。ARM TrustZoneTM 技术使系统和软件能够划分为安全世界（Secure world）和普通世界（Normal world）。安全软件可以访问安全和非安全内存以及硬件资源，而普通软件只能访问非安全内存和资源。这些安全状态与现有的线程模式（Thread mode）和处理程序模式（Handler mode）正交（后文将详细介绍这两种运行模式），从而允许在安全和非安全状态下都存在线程模式和处理程序模式。

¹¹来源 ST AN3430

ARM TrustZone 技术并不涵盖安全性的所有方面。例如，它不包括加密。在具有 TrustZoneTM 的 ARMv8-M 架构设计中，对系统安全至关重要的组件可以放置在安全世界中。例如，这些关键组件可能包括：

- 安全引导加载程序（Secure boot loader）
- 秘密密钥（Secret keys）
- 闪存编程支持（Flash programming support）
- 高价值资产（High value assets）

其余的应用程序通常放置在普通世界中。

#### 1.1.1.10 CMSIS

ARM 平台（无论是对于芯片供应商还是应用开发人员）的一个关键优势在于存在一套完整的开发工具（编译器、运行时库、调试器等），这些工具可以在多个供应商之间重用。

ARM 还在积极致力于在微控制器供应商之间标准化软件基础设施。Cortex 微控制器软件接口标准（Cortex Microcontroller Software Interface Standard, CMSIS）是 Cortex-M 处理器系列的供应商无关的硬件抽象层（hardware abstraction layer），并指定了调试器接口。CMSIS 由以下组件组成：

- CMSIS-CORE：Cortex-M 处理器内核和外设的 API。它为 Cortex-M0/0+/3/4/7/23/33 提供标准化接口。
- CMSIS-Driver：定义通用外设驱动程序接口，使中间件可以在受支持的设备之间重用。该 API 与实时操作系统（real-time operating system, RTOS）无关，并将微控制器外设连接到实现通信堆栈、文件系统或图形用户界面等功能的中间件。
- CMSIS-DSP：包含 60 多种函数的 DSP 库集合，适用于各种数据类型：定点（分数 q7, q15, q31）和单精度浮点（32 位）。该库可用于 Cortex-M0、Cortex-M3 和 Cortex-M4。Cortex-M4 实现针对 SIMD 指令集进行了优化。
- CMSIS-RTOS API：实时操作系统的通用 API。它提供标准化的编程接口，可移植到许多 RTOS，因此使软件模板、中间件、库和其他组件能够在受支持的 RTOS 系统之间工作。我们将在第 23 章中讨论这个 API 层。
- CMSIS-Pack：使用名为“PDSC”的基于 XML 的包描述文件，描述文件集合（即“软件包”）中与用户和设备相关的部分，该集合包括源文件、头文件、库文件、文档、闪存编程算法、源代码模板和示例项目。开发工具和 Web 基础设施使用 PDSC 文件提取设备参数、软件组件和评估板配置。

<!-- page: 50 -->

- CMSIS-SVD：外设的系统视图描述（System View Description, SVD）。在 XML 文件中描述设备的外设，可用于在调试器中创建外设感知，或创建包含外设寄存器（register）和中断（interrupt）定义的头文件。
- CMSIS-DAP：调试访问端口（Debug Access Port）。连接至 CoreSight 调试访问端口的调试单元的标准固件。CMSIS-DAP 作为单独的包分发，非常适合集成在评估板上。
- CMSIS-NN：神经网络。由于最新 Cortex-M4/7 内核计算能力的提升，基于神经网络的解决方案即使在嵌入式机器学习应用中也越来越流行。CMSIS-NN 是一组高效的神经网络内核，旨在最大化 Cortex-M 处理器内核上神经网络的性能并最小化其内存占用。
