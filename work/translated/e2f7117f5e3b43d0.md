#### 1.1.1.4 Thumb-2 与内存对齐

从历史上看，ARM 处理器提供 32 位指令集。这不仅允许拥有丰富的指令集，而且保证了在执行涉及算术运算以及内核寄存器与 SRAM 之间内存传输的指令时获得最佳性能。然而，32 位指令集在固件的内存占用方面是有代价的。这意味着使用 32 位指令集架构（Instruction Set Architecture, ISA）编写的程序需要更多的闪存存储字节数，这会影响微控制器（MCU）的功耗和整体成本（硅晶圆价格昂贵，制造商不断缩小芯片尺寸以降低其成本）。

为了解决这些问题，ARM 引入了 Thumb 16 位指令集，它是常用 32 位指令集的一个子集。Thumb 指令每条长度为 16 位，并自动“转换”为对处理器模型具有相同效果的相应 32 位 ARM 指令。这意味着 16 位 Thumb 指令在实时情况下被透明地扩展（从开发者的角度来看）为完整的 32 位 ARM 指令，且没有性能损失。Thumb 代码的大小通常是 ARM 代码的 65%，并在从 16 位内存系统运行时提供后者 160% 的性能；然而，在 Thumb 中，16 位操作码的功能较少。例如，只有分支可以是条件性的，并且许多操作码被限制为只能访问 CPU 通用寄存器的一半。随后，ARM 引入了 Thumb-2 指令集，它是 16 位和 32 位指令

<!-- page: 42 -->

集在一种操作状态下的混合。Thumb-2 是一种可变长度指令集，与 Thumb 指令集相比提供了更多的指令，并实现了相似的代码密度。

![Image from PDF page 42](../images/page-0042-image-01.jpeg)

图 1.7：对齐内存访问与非对齐内存访问的区别

Cortex-M3/4/7 被设计为支持完整的 Thumb 和 Thumb-2 指令集，其中一些还支持专门用于浮点运算（Cortex-M4/7）和单指令多数据（SIMD）运算（也称为 NEON 指令）的其他指令集。

Cortex-M3/4/7 内核的另一个有趣特性是能够进行非对齐内存访问。基于 ARM 的 CPU 传统上能够访问字节（8 位）、半字（16 位）和字（32 位）的有符号和无符号变量，而不会像 8 位 MCU 架构那样增加汇编指令的数量。然而，早期的 ARM 架构无法执行非对齐内存访问，导致内存位置的浪费。

为了理解这个问题，请考虑图 1.7 中的左侧图表。这里有八个变量。内存对齐访问意味着，要访问字变量（图中的 1 和 4），我们需要访问 32 位（4 字节）的倍数地址。也就是说，字变量只能存储在 0x2000 0000、0x2000 0004、0x2000 0008 等位置。任何尝试访问不是 4 的倍数的位置都会导致 UsageFaults 异常。因此，以下 ARM 伪指令是不正确的：

```text
STR R2, 0x20000002
```

半字访问也是如此：可以访问存储在 2 字节倍数位置的内存位置：0x2000 0000、0x2000 0002、0x2000 0004 等。这种限制会导致 RAM 内存中的碎片化。为了解决这个问题，基于 Cortex-M3/4/7 的 MCU 能够执行非对齐内存访问，如图 1.7 中的右侧图表所示。我们可以看到，变量 4 从地址 0x2000 0007 开始存储（在早期 ARM 架构中，这仅对单字节变量是可能的）。这允许我们将变量 5 存储在内存位置 0x2000 000b，从而导致变量 8 存储在 0x2000 000e。内存现在被紧密打包，我们节省了 4 字节的 SRAM。

然而，非对齐访问仅限于以下 ARM 指令：

- LDR, LDRT
- LDRH, LDRHT
- LDRSH, LDRSHT

- STR, STRT
- STRH, STRHT

#### 1.1.1.5 流水线

每当我们要谈论指令执行时，我们都在做一系列非平凡的假设。在执行指令之前，CPU 必须从内存中获取并解码它。这个过程消耗几个 CPU 周期，具体取决于内存和内核 CPU 架构，这会增加到实际指令成本（即执行给定指令所需的周期数）中。

现代 CPU 引入了一种并行化这些操作的方法，以提高其指令吞吐量（单位时间内可以执行的指令数量）。基本指令周期被分解为一系列步骤，就好像指令沿着流水线行进一样。而不是按顺序处理每条指令（一次一条，在完成一条指令之前不开始下一条），每条指令被拆分为一系列阶段，以便不同的步骤可以并行执行。

![Image from PDF page 43](../images/page-0043-image-01.jpeg)

图 1.8：三级指令流水线

所有基于 Cortex-M 的微控制器都引入了某种形式的流水线。最常见的是三级流水线，如图 1.8 所示。Cortex-M0/3/4 支持三级流水线。专门用于低功耗 MCU 的 Cortex-M0+ 内核提供二级流水线（尽管流水线有助于减少与指令获取/解码/执行周期相关的时间成本，但它引入了必须在低功耗应用中最小化的能量成本）。Cortex-M7 内核提供六级流水线。

在处理流水线时，分支是一个需要解决的问题。程序执行的所有内容都是关于采取不同的路径；这是通过分支（如果相等则跳转）实现的。不幸的是，分支会导致流水线流失效，如图 1.9 所示。最后两条指令已被加载到流水线中，但由于选择了可选的分支路径而被丢弃（我们通常将它们称为分支阴影）
